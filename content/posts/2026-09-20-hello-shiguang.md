开一个属于自己的角落，这件事我想了很久。

社交平台上的文字，总带着一点表演性质——发出去的那一刻，就开始在意它有多少人看见。而这里不一样：没有推荐算法，没有阅读量，没有「你可能也喜欢」。只有一个人，把想清楚的事写下来。

## 准备写什么

内容会分成两条线，交替出现。

**技术笔记**，主要是这几类：

- 工程实践：某个问题是怎么被解决的，为什么选这个方案而不是那个
- 踩坑复盘：报错、排查、最后定位到的那一行代码
- 源码与原理：读到有意思的实现，顺手拆一拆
- 工具与效率：把日常重复劳动压缩掉的那些小东西

**生活随笔**，则是另一条线：

- 读过的书、看过的电影，以及它们留下的痕迹
- 周末去了哪里，路上想了些什么
- 一些没什么用但很想说的碎碎念

> 技术文章会被时间淘汰，生活记录会被自己遗忘。写下来，至少能对抗其中一样。

## 为什么不用现成的平台

用过不少博客系统，最后都停更了。原因大概都差不多：

| 方案 | 停更原因 |
| --- | --- |
| 第三方博客平台 | 数据不在自己手里，广告越来越重，改版后排版全乱 |
| 通用建站模板 | 想改一点细节就得跟模板作者的设计意图搏斗 |
| 本地静态生成器 | 写文章要跑构建，想发一条灵感还得先打开编辑器 |

这次干脆自己写。要求不多：

1. **文章以纯 Markdown 文件保存**，随时可以打包带走，不锁死在某个数据库里
2. **写作即发布**，把 `.md` 丢进目录，刷新页面就看到了
3. **结构上留好扩展口**，以后想加评论、全文检索、图片管理，不用推倒重来

## 技术选择

最后落在 Node.js + Express 上，是个不新潮但很稳的组合。

```js
// 内容层是整个站点的核心，也是唯一需要替换的层
const posts = content.getAllPosts();   // 读 Markdown
const post  = content.getPost(slug);   // 取单篇
const hits  = content.search(keyword); // 全文检索
```

页面由服务端直接渲染成 HTML，而不是丢一个空壳让浏览器去拼。这样做的好处很实际：搜索引擎能读懂，首屏不用等 JavaScript，关掉脚本也能正常阅读。

安全性上也没有偷懒：

- 用 `helmet` 下发 CSP，脚本一律走外部文件，不给内联脚本留口子
- 所有用户输入（搜索关键词、URL 参数）都经过转义再进入模板
- 正文里的外链自动带上 `rel="noopener noreferrer nofollow"`

## 关于更新频率

不做承诺。写得出来就写，写不出来就让它空着。

一个长期荒废的博客不可耻，为了维持更新而凑字数才可耻。

---

如果你也在犹豫要不要搭自己的站点，我的建议是：**先写三篇，再决定要不要搭**。很多人卡在选框架上，其实真正的问题是还没开始写。
